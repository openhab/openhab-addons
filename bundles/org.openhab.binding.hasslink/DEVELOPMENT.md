# Setting up Home Assistant for Fixture Extraction

The generated test fixtures containing Home Assistant WebSocket payloads are stored under:
`src/test/resources/org/openhab/binding/hasslink/internal/fixtures/`

| Directory / Target     | Generated by                  | Description                                           |
|:-----------------------|:------------------------------|:------------------------------------------------------|
| `ha_fixtures/`         | `dump_all_registries.py`      | HA registries and state dumps                         |
| `fixtures/`            | `dump_fixtures.py`            | Uncompressed payloads (`subscribe_events`)            |
| `compressed_fixtures/` | `dump_compressed_fixtures.py` | Compressed payloads (`subscribe_entities`)            |
| `custom_fixtures/`     | Manually created              | Custom fixtures not covered by the generated payloads |

---

## How to Recreate Test Fixtures

### 1. Spin up Temporary Home Assistant & Auto-Generate Token

Run the automated setup script from the `tools/` directory. This bypasses the browser onboarding wizard, enables the `demo` integration, starts Home Assistant on port `9123`, and automatically writes the access token to `tools/.token`.

```sh
cd tools/
bash bootstrap_ha.sh
```

---

### 2. Set Up Python Environment and Run Dumper Scripts

Execute the dumper scripts using the automatically generated `.token`:

```sh
# 1. Create and activate Python virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 2. Install required dependency
pip install websocket-client

# 3. Generate JSON test fixtures (outputs directly to src/test/resources/.../fixtures/)
python dump_all_registries.py
python dump_fixtures.py
python dump_compressed_fixtures.py
```

---

### 3. Cleanup

Stop the Docker container when finished:

```sh
docker stop hasslink_test_ha
docker volume rm hasslink_ha_fixture_data
```
